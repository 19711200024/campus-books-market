>

## 二、功能演示（2 分钟）

### 2.1 首页与浏览搜索（25 秒）

**画面**：
- 打开浏览器，访问平台首页
- 展示首页：顶部导航栏、统计数据（在售书籍数、用户数）、推荐书籍区域
- 滚动到书籍列表区，展示书籍卡片网格
- 在搜索框输入"数据结构"，展示搜索结果
- 点击左侧筛选栏，选择分类"教材"、成色"九成新"，展示筛选后的结果
- 切换排序方式为"价格从低到高"

**台词**：

> 首先打开平台首页。首页展示了当前平台的在售书籍数量和用户数，下方是系统根据你的学院推荐的教材，以及最新上架的书籍。
>
> 我们可以通过关键词搜索，比如搜"数据结构"，就能找到所有相关教材。还可以按分类和成色筛选，排序方式也很灵活。
>
> 点击任意一本书，进入详情页。

### 2.2 书籍详情与购买（25 秒）

**画面**：
- 点击一本书进入详情页
- 展示：书籍大图、书名、作者、价格、原价、成色标签、描述、卖家信息（含信用分）
- 点击"收藏"按钮，提示收藏成功
- 点击"想要"按钮，弹出下单确认弹窗
- 选择自提点"图书馆东门"，点击确认下单
- 切换到"我的订单"页面，展示刚创建的待确认订单

**台词**：

> 详情页展示了书籍的完整信息和卖家的信用分。遇到感兴趣的书可以先收藏。
>
> 决定购买的话，点击"想要"，选择校内自提点，确认下单。这时候订单处于"待确认"状态，等待卖家确认。

### 2.3 卖家视角与订单流转（25 秒）

**画面**：
- 退出当前账号，登录卖家账号
- 进入"我卖出的"订单页面，展示待确认订单
- 点击"确认"按钮，订单状态变为"已确认"
- 切回买家账号，进入订单详情，点击"确认完成"
- 展示书籍状态自动变为"已售出"

**台词**：

> 现在切换到卖家账号。卖家在"我卖出的"页面看到买家的下单请求，确认交易意向后，订单变为"已确认"。
>
> 双方线下见面交货后，买家点击"确认完成"，订单状态变为"已完成"，这本书的状态也自动更新为"已售出"。整个交易流程闭环。

### 2.4 站内消息与发布（25 秒）

**画面**：
- 在买家账号下，进入某本书的详情页，点击"留言"
- 发送一条消息："你好，这本书还在吗？周末可以交易吗？"
- 切换到卖家账号，查看站内消息，展示未读红点
- 打开消息对话，回复买家
- 切换到卖家账号，点击"发布书籍"，展示发布表单
- 输入 ISBN，展示自动填充的书名和作者
- 填写价格、成色、上传 2 张书籍照片，点击发布

**台词**：

> 买卖双方还可以通过站内消息沟通细节。买家在书籍详情页留言询问，卖家会收到未读提醒，在线回复。
>
> 发布书籍也很方便。输入 ISBN 号，系统自动填充书名和作者，卖家只需要补充价格、成色和实拍照片，点击发布即可上架。

## 三、开发过程讲解（1 分钟）

### 画面说明
- 展示项目目录结构（VS Code 文件树展开）
- 展示 Git 提交记录截图（体现团队协作）

### 台词

> 这个项目采用前后端分离架构开发。
>
> **后端**基于 Node.js + Express 框架，数据库选用轻量级的 SQLite，通过 better-sqlite3 驱动连接。认证使用 JWT，密码用 bcrypt 加密存储。
>
> **前端**使用 Vue 3 + Vite 构建，UI 组件库用 Element Plus，状态管理用 Pinia，路由用 Vue Router 4。
>
> 我们四人小组分工协作：张明负责后端架构和 API 设计，李华负责前端架构和核心页面，王芳负责交易和消息模块的前端开发，我负责文档、测试和视频制作。
>
> 开发过程中我们也大量使用了 AI 工具辅助，包括需求梳理、数据库设计、代码模板生成和 Bug 排查，效率提升明显。

## 四、核心代码讲解（1 分钟）

### 4.1 JWT 认证中间件（20 秒）

**画面**：
- 打开 `backend/middleware/auth.js`
- 高亮关键代码：`jwt.verify()` 验证 Token、`req.user` 挂载、401 错误响应

### 台词

> 首先是 JWT 认证中间件。登录成功后，后端用 `jwt.sign` 签发一个 7 天有效的 Token 返回给前端。
>
> 前端每次请求都会在 Header 里带上这个 Token，后端中间件用 `jwt.verify` 验证，验证通过就把用户信息挂到 `req.user` 上，后续路由就能拿到当前用户是谁。验证失败直接返回 401。

### 4.2 书籍搜索 API（20 秒）

**画面**：
- 打开 `backend/routes/books.js` 或对应控制器
- 高亮关键代码：动态拼接 WHERE 条件、`LIKE` 模糊查询、参数化查询、分页 LIMIT/OFFSET

### 台词

> 第二个是书籍搜索接口。我们根据查询参数动态拼接 SQL：有关键词就加 LIKE 模糊匹配书名、作者和 ISBN；有分类和成色筛选就追加等值条件。
>
> 注意我们用的是参数化查询，用 `?` 占位符，防止 SQL 注入。最后加上 LIMIT 和 OFFSET 实现分页。

### 4.3 前端路由守卫（20 秒）

**画面**：
- 打开 `frontend/src/router/index.js`
- 高亮 `router.beforeEach` 守卫代码、`meta.requiresAuth` 判断

### 台词

> 第三个是前端路由守卫。Vue Router 的 `beforeEach` 全局守卫会在每次路由跳转前检查：如果目标页面需要登录（`requiresAuth: true`），而用户没有 Token，就自动跳转到登录页。
>
> 这样发布、订单、收藏这些需要登录的页面就不会被未登录用户直接访问了。

## 录制注意事项

1. **提前准备种子数据**：确保有至少 3 个测试账号、20+ 本测试书籍、若干测试订单和消息，避免演示时空数据尴尬；
2. **操作流畅**：提前完整走一遍演示流程，确保鼠标移动准确、点击不犹豫；
3. **网络稳定**：录屏前关闭其他占用带宽的应用；
4. **麦克风测试**：提前试录一段，确认音量合适、无杂音；
5. **浏览器清理**：演示前清除浏览器书签栏干扰，关闭无关标签页；
6. **字体放大**：浏览器页面缩放调到 110%-125%，确保录屏后文字清晰可辨；
7. **备份方案**：如果现场演示环境出问题，准备好录屏视频作为兜底。
